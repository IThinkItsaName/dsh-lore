# 目标文件规格（`目标.md`）

> **状态**：设计已确认，**已实现** —— `journal.py check` 校验本文件（§三 那三条 ERROR），
> `references/conventions.md` 的「目标」一节是使用者视角的说明。
>
> 触发这次设计的问题是「需不需要专门安排一个文件夹存放长期目标、阶段与完成情况」。
> 结论是**不新开文件夹**，而是在容器里给目标一个**自己的小节文件**，且**需要时才建**。

## 零、为什么不是新文件夹

| 理由 | 说明 |
|---|---|
| **语料零先例** | 三个语料 224 个文件里，**没有任何**目标/路线图/里程碑产物；`70-dshpack-and-security-plan.md` 那类是**单篇记录**，不是目标产物 |
| **会把一件事拆两处** | 目标的进展必然与记录纠缠（一篇记录推进哪个目标、哪个阶段收口）。再开一处就会出现"目标和记录谁是真的" —— 这正是本项目反复在修的那类缺陷（`mode` 两处、`effective` 两处） |
| **破坏"一个项目一个容器"** | 那条约定让 `journal.py` 知道去哪找东西。两个容器意味着每个命令都要知道读哪一个 |

**但缺口是真的**：现有体系能装下"**一个**长期目标按阶段推进"（台账 `## 项目背景` 的
`目标：` + 索引的 `### <阶段名>` + 状态块的 `阶段 / 版本`），**装不下"多个并行长期目标
各自处于不同阶段"** —— 因为状态块全文件只能有一个，且只有一个 `阶段 / 版本` 字段。

## 一、文件

| | |
|---|---|
| 落点 | `<容器>/目标.md`（与 `README.md` / `ARCHIVE.md` / `LEGACY.md` 同级） |
| 创建 | **需要时才建。** 没有它是正常的，`check` 不报任何东西 |
| 谁写 | 人或 agent 手工维护 —— **不是**台账的替代品 |

## 二、形式

两层：**目标 → 阶段**。一个目标有多个阶段时，它占多行，目标名只在首行写一次。

```markdown
# 目标

| 目标 | 阶段 | 状态 | 相关记录 |
|---|---|---|---|
| 让 worklog 可公开发布 | 规范重写 | 已完成 | 0007, 0012 |
|  | 设置页 | 进行中 | 0021 |
|  | 文档收尾 | 未开始 | — |
| 支持多语言 | — | 进行中 | 0009 |
| 远程协作 | — | 未开始 | — |
```

### 列

| 列 | 必填 | 说明 |
|---|---|---|
| 目标 | 首行必填 | 长期目标名。**续行为空**表示这一行是该目标的下一阶段 |
| 阶段 | 可选 | 该目标的一个阶段。单阶段目标写 `—` |
| 状态 | 必填 | 四选一：`未开始` / `进行中` / `已完成` / `已放弃` |
| 相关记录 | 可选 | 篇号，逗号分隔；没有写 `—`。也接受 `wl/0007` 这种回引写法 |

### 状态是**人工维护**的

不从引用的记录推导。理由：推导规则一旦复杂就会算错，而算错的目标表比手写的更不可信。

## 三、`check` 要校验什么

只校验**能机械判定**的：

1. **引用的篇号必须真实存在** —— 指向不存在的记录就报错。这是核心价值：
   否则目标表会悄悄腐化成一张写着不存在篇号的清单。
2. **状态必须是那四个之一** —— 拼错或发明新状态就报错。
3. **首行必须有目标名** —— 精确的机械判据是：**某一行「目标」为空，而它之前还没有任何一行写出过目标名**。

   > 这一条容易写歧义，所以把边界说死：**不能要求"上一行必须有目标名"** ——
   > 那会把本文件 §二 示例的第 3 行（`|  | 文档收尾 | 未开始 | — |`）判成错，
   > 而它正是合法的第二阶段行。空目标单元格本身**无法与"忘了写新目标名"区分**，
   > 所以只能检出"从没出现过父行"这一种。一个单调的 `seen_goal` 标志即可。

**三条都是 ERROR** —— 全部可机械判定，与死链、编号重复同级。它们**不需要 `--strict`**，
也**不参与渐进原则**（目标文件不是旧记录）。

**明确不校验**（判定不了，或校验了会教人忽略告警）：

- 阶段名与索引里的 `### <阶段名>` 是否一致
- 状态与记录内容是否相符（比如"引用篇号都已归档，状态还写进行中"）
- 目标是否重复

**问题一律进 `check` 的计数**，与该文件缺省时报 0 个问题一致。

### 相关记录的取词法（故意从严）

**只把整个单元格就是 `\d{1,4}`（或 `wl/\d{1,4}`）的当作引用**，其余一律跳过。
不从行内任意位置抽数字 —— 那会让日期式容器误报（`2026-09-06-x.md` → "篇号 2026 不存在"）。

**宁可漏报，不要误报**：误报会教人忽略告警。

## 四、为什么这个设计能零冲突落地

排除机制本来就是**通用规则**，不是写死的文件名列表：

```python
def is_record_name(name):        # journal.py:616
    return bool(DATE_NAME_RE.match(name) or NUM_FILE_RE.match(name))
```

`目标.md` 不匹配编号式/日期式 → 自动返回 `False` → 不被当记录、不做半解析。
**不用改任何常量。**

索引覆盖检查也安全（`journal.py:1512`）：

```python
if has_index_section:
    for rec in recs:            # 只遍历真记录
        if is_active_entry(...) and entry_link(...) not in read(index):
            rep.add("WARN", ...)
```

只遍历 `recs`，所以 `目标.md` **不会被要求进索引**，不会刷出假 WARN。

## 五、不做什么

- **不放进 `.config.json`** —— 目标表是内容，不是配置。
- **不设独立目录** —— 见 §零。
- **不让它进入 `L_INDEX` 的强制项** —— 缺它是正常的。
- **不做目标级的 `mode`** —— 精细度是**容器**的属性，不是目标的。
