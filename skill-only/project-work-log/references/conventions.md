# 约定（Conventions）

> 这些是硬约定。**没有工具替你执行**：怎么算通过、怎么算不通过，见本文件末尾的「手工复核清单」。
> 偏离前先想清楚代价，偏离后要在记录里写明。

## 目录布局

记录体系收在**一个**容器目录里：过程记录、台账、经验层、日志都在它下面。

```
<项目根>/
├── README.md                 ← 项目 README（加一行指向 work_log/README.md）
└── work_log/                 ← 容器（默认名，可配置）
    ├── README.md             ← 台账（建议）：索引表 + 同主题簇 + 滚动待办 + 当前状态（可选）
    ├── 0001-<slug>.md        ← 过程记录，**就在容器根**（编号式；一篇 = 一个可交付单元）
    ├── YYYY-MM-DD-<slug>.md  ← 过程记录（日期式，同一容器里建议只用一种）
    ├── STATE-HISTORY.md      ← 被替换下来的旧「当前状态」块
    ├── ARCHIVE.md            ← 归档索引（归档时手工补行）
    ├── LEGACY.md             ← 旧记录声明（可选，见「渐进原则」）
    ├── <YYYY>/…              ← 按年分卷后的记录
    ├── <stage>/…             ← 归档记录：阶段目录直接建在容器下，**没有** archive/ 一层
    ├── lessons/              ← 经验层（分册索引 + 分册 + 阶段复盘）
    │   ├── README.md
    │   ├── 01-<topic>.md
    │   └── 99-retrospectives.md
    └── logs/                 ← 日志与运行产物（按来源分子目录，见「日志归位要求」）
        └── <来源>/
```

- 容器名默认 `work_log/`，可以改名；经验子目录默认 `lessons/`，也可以改名。
  改名只在项目里说清楚一次，之后一律用新名。**不要两个名字并用。**
- **记录一律住容器根**（分卷后是 `<YYYY>/…`）
  ——正好是旧布局 `journal/0001-x.md` / `journal/2026/0001-x.md` 的下一层。
- **归档 = 搬到 `work_log/<stage>/`**：阶段目录直接建在容器下，不再有 `archive/` 中间层。
  由此推出一条判据：**相对容器路径的第一段是 4 位年份 ⇒ 活跃；其余子目录 ⇒ 已归档**。
  `lessons/`、`logs/` 是容器内的**非记录**目录，`README.md`、`STATE-HISTORY.md`、`ARCHIVE.md`、
  `LEGACY.md` 也不是记录——它们各自按文件名与路径排除，绝不能被当成「一个已归档阶段」。
  ⚠ 这条判据的代价是：**不要在容器下另建目录来放记录**（草稿也放容器根）。
  容器下的子目录只有三类——年份卷 `<YYYY>/`、归档阶段 `<stage>/`、以及 `lessons/` `logs/`；
  在别处塞记录文件会被当成「已归档」。

### 两种命名约定（两种都要认得，一个容器只用一种）

| 约定 | 文件名 | H1 必须写成 | 实测范围 |
|---|---|---|---|
| **编号式** | `NNN-<slug>.md`，编号 1–4 位（纯中文标题可用 `0007.md`） | `# NNN · <标题>` | 原型 207 篇 + `comfy` 30 篇 |
| **日期式** | `YYYY-MM-DD-<slug>.md`，日期必填 | `# YYYY-MM-DD <标题>`；日期后可接一个行内实验号，如 `# 2026-09-20 R21：标题` | `embeding try` 71 篇（68 篇带日期） |

规则：

1. **H1 与文件名必须一致**。编号式比篇号，日期式比日期。
2. **文件名两种都不匹配的，不是记录**，直接跳过——不要硬套、不要猜。
   `模型效果总表.md`、`INDEX.md`、`README.md` 都属于这一类。
3. **编号单调递增、永不复用、归档不改号**——**只在编号式容器里生效**。日期式容器不分配编号。
4. 同一日期可以有多篇（实测 `2_multi_attention` 一天 8 篇），靠标题区分。
5. **一个容器内建议只用一种**：混用会让排序与索引变乱；混用不算错。
6. 标题用中文，可含英文/代码词；避免 Windows 非法字符 `\ / : * ? " < > |`。
7. 回指地址：**编号式写 `wl/NNNN`**，**日期式写文件名**（`2026-09-06-门控两段式.md`）。
   **不引入短锚点编号**——文件名/编号已经唯一自明，再加一层是多余。

### 旧布局的读取回退（只读，不迁移）

老项目还在 `journal/` + 顶层 `lessons/` 时，**不改名、不移动、不警告**，直接按下面的顺序认：

| 解析对象 | 顺序 |
|---|---|
| 容器 | 项目里说清的容器名 → `<根>/work_log/` → `<根>/journal/` → `<根>/work-log/` |
| 经验目录 | 项目里说清的经验目录名 → `<容器>/lessons/` → `<根>/lessons/` |

- 旧布局的 `journal/archive/<stage>/` 仍按「第一段不是年份 ⇒ 已归档」判为归档，无需特判。
- 旧布局的 `journal/archive/STATUS-HISTORY.md`、`journal/archive/README.md`、
  `journal/archive/COLD-STORE.md` 已存在时**继续沿用原文件**，避免把同一段历史劈成两份。
  文件不存在时才落到容器根的新位置。
- 迁移留给人：用户明确要求时再搬；不要自动迁移。

## 两个计数器（不要混）

| 名字 | 含义 | 在哪 | 规则 |
|---|---|---|---|
| **篇号** | 记录文件编号，索引与回指的地址（**只有编号式容器有**） | 文件名 + 标题 `# 0007 · ...` | 每写一篇 +1；永不复用；跨归档不变 |
| **迭代号** | 项目层面的工作单元编号（一个可交付的迭代） | 记录入口的迭代字段（默认 `迭代: N`） | 一个迭代可以对应多篇（如「执行 + 验收修复」）；一次性/不编号的工作写 `迭代: -` |

回指：编号式写 `wl/NNNN`（篇号），日期式写文件名。不要写「迭代 N」，否则两者会混淆。

**两个计数器独立发展，从不对应。** 原型 `README.md` 曾写「编号与变更集对应」，实测**推翻**：
`变更集` 号等于篇号 **0 例**；篇 207 → 变更集 182（差 25）；有 `变更集` 字段的只有 26/162，
其中 **146 篇写「变更集：无」**。这条铁律（篇号与迭代号分开）存在的意义正是**防止**你以为它们对应。

`变更集` 只是迭代字段的一个**别名**，而且是**可选**的：它是软件项目的叫法，
实测 146 篇写「无」说明这份记录远不止追踪代码变更——它是**工作记录**，不是变更日志。
缺这个字段**不算错**。

**迭代字段的别名**（都能读，写入时用默认的 `迭代：`）：`迭代 / 变更集 / 批次 / 阶段 / 版本 / 里程碑`。
不同领域用不同叫法：软件用「变更集/版本」，研究用「批次/阶段」，写作/设计可能用「里程碑」。

## 词表可以自己扩

**别名表是用户可扩的，这就是扩法。**

上面那组迭代别名、下面「验证段」那组标题别名，都是**开放的词表**，不是固定枚举。
项目里有自己领域的叫法时，直接加进去，然后**在项目里写明你加了什么**。

怎么做（三步）：

1. **定下词**：挑一个你领域里真的会用的词，例如迭代叫「冲刺」，验证小节叫「验收」。
   只加真的会用到的，别一次列十个。
2. **落到两个地方**：
   - 项目自己的记录约定里（根 `README.md`、`CLAUDE.md`、`AGENTS.md` 之一，或容器 `README.md` 顶部）
     加一行说明：本项目的迭代字段写 `冲刺：`，验证小节写 `## 验收`。
   - 本文件或项目自己复制的一份约定里，把这两个词补进对应的别名列表。
3. **一次只用一个词**：同一个项目里选定就别来回换。新旧混用会让检索和归档都对不上。

两点注意：

- **写入仍用默认词**（`迭代：`），除非项目明确统一成别的。这样别人接手时一眼认得出入口行。
- 加词**不会**让旧记录失效：旧记录用的是老词，照样在。
  这也是为什么别名表要「认全部、写一个」——读的时候宽松，写的时候统一。

## 记录精细度（一篇 = 什么）

一篇记录覆盖多长的工作，由**台账里的一个字段**决定，不靠临时商量。

| 档位 | 一篇 = | 一次会话的预期产出 |
|---|---|---|
| **`full`（默认）** | 一个可交付的子单元 | 2–3 篇；同一天多篇很正常 |
| `session` | 一次会话，或一个可交付成果 | 最多 1 篇；同一会话的第二件事**追加到同一篇** |
| `digest` | 一个阶段（跨多次会话） | 多次会话并成一篇 |
| `milestone` | 一个阶段收口 | 只留决策与经验 |

**为什么默认是 `full`**：实测原型 111 篇带日期的记录分布在 12 个日期上（平均 9.2 篇/天，
最多一天 **34 篇**），`embeding try` 也有一天 8 篇。`session` 档会把那 34 篇压成一篇——
那不是更简洁，那是把 34 个可独立查阅的单元埋进一个文件。粗档位留给确实低强度的项目
（写作、调研、运维）。

**存在哪**：台账 `## 当前状态` 的第八个固定字段 `精细度`。值一律写拉丁规范值
（`full` / `session` / `digest` / `milestone`）。可选的一行原因跟在同一个值里：
`session（原因：阶段收口）`。

**精细度只认这四个拉丁值。** 中文别名（`完整` / `会话` / `摘要` / `里程碑`）只是帮人看懂，
**台账里不要写中文档位名** —— 写到台账里的必须是那四个拉丁值之一。

不在状态块里的情况**不算错**：字段缺失、或值认不出来时按默认档 `full` 处理。
所以这次改动之前写下的台账一律照常工作。

**不变量：档位只放宽「要不要另起一篇」，不放宽验证要求。**
任何档位下，一篇记录都必须有可核对的验证小节（见「验证段（必填）」）。
档位影响的是记录**数量**，以及可选叙述写多细——不是能不能少写验证。

**粗档位的额外义务**：`digest` / `milestone` 必须写明这一轮**刻意没有记录什么**，
例如 `未记录：本轮的两处配置调整，见提交 abc1234`。写在正文任意位置即可，
写成 `## 未记录` 小节或行内一句都行（`未记录` / `未记` / `未收录` 三种写法都认）。
理由：粗档位把多轮会话并成一篇，一定有东西没进正文；不写这一句，读者无法区分
「确实没有」和「忘了记」。

**怎么切**：会话里口头说一句（「这次记详细点」→ `full`）只管这一轮；
要让之后的会话都按新档位走，就把台账那一行改掉。手工做法见「手工操作规程」的「切换精细度」。

## 记录生命周期

```
草稿（进行中）  →  收口（closed）  →  （可选）归档
```

- **草稿**：标题下方元数据可边做边补；允许写「未验证/待确认」。
- **收口**：收尾清单（见 SKILL.md）全部完成后才算 closed。收口后**不改写已发生的结论**。
- **更正**：新证据推翻旧结论时，**追加** `## 更正` 段（日期 / 原结论 / 新证据 / 现结论），并同步台账与 lessons；
  绝不允许把旧文字直接抹掉。
- **归档**：阶段收口、索引表停止增长时，把整阶段的记录搬到 `work_log/<stage>/`；
  同步改索引链接、写归档索引（`ARCHIVE.md`），并把链接全查一遍。

## 日志归位要求

**任何项目产生的持久日志 / 运行产物都进容器，并且分类存放**：

- 位置固定为 `work_log/logs/`，**一个来源一个子目录**：`work_log/logs/<工具名>/`、`work_log/logs/<服务名>/`。
  例：`work_log/logs/build/`（构建输出）、`work_log/logs/crawler/`（采集记录）、`work_log/logs/bench/`（压测结果）。
- **不许**把 trace、`.log`、导出文件随手丢在项目根，也**不许**写到项目之外（家目录、系统临时目录、桌面）
  ——那等于把证据放在版本控制与备份之外，别人接手时找不到。
- 日志目录**不是记录**：`logs/` 下的文件不编号、不进索引表、不参与编号断档检查。
  日志与记录的关系是「记录引用日志」，不是「日志也算一篇」：在记录里写清路径与关键结论即可。
- **测试用的临时夹具不属于这里**：丢弃型 fixture、一次性样本、可随时重建的中间产物，不是记录，
  不要写进 `work_log/`（更不要提交）。
- **日志里不得出现绝对机器路径**（`C:\Users\<人名>\...`、`/home/<人名>/...`）。记录本来就要可移植，
  日志同理：一律写**相对项目根**的路径，或写明环境变量；脱敏后再落盘。

## 整理与清理（量增长后）

**证据不删**是硬规则：清理 = 移走 + 汇总 + 留清单，不是删除。

| 动作 | 手工做什么 | 做完的判据 |
|---|---|---|
| 阶段归档 | 把篇号区间的记录移进 `work_log/<stage>/`；改写仓库里所有指向它们的链接（索引、lessons、以及被移动记录自己的出站链接）；在 `ARCHIVE.md` 补一行 | 链接全查一遍，0 死链 |
| 索引瘦身 | 把**整节都已归档**的小节折叠成一行区间：`\| [02-research/](02-research/) \| 0027–0045（19 篇，已归档） \|` | 只动索引；混合小节、含死链的小节、非记录行、已折叠过的目录行都不要碰 |
| 按年分卷 | 把活跃记录移进 `work_log/<YYYY>/`（年份取自入口行的 `日期：`），改写链接 | `wl/NNNN` 回指不受影响 |
| 冷存 | 先只**报告**候选；得到明确要求后才打包、留清单、把原件移出 | 候选判据见下第 3 条；**绝不删除** |

判据与顺序：

1. **归档判据 = 阶段收口**（索引表不再增长），不用「多少天没引用」这类经验值。
2. 归档后立刻做索引瘦身：否则索引会随归档线性膨胀（实测每篇约 600 字符）。
3. 冷存判据：已归档 + **未被 lessons 引用** + 足够久（经验值是 180 天以上）。
   未被引用 ≠ 没价值，所以**第一步永远只是报告候选**，要人明确确认后才动手。
4. 搬家后必须把 md 链接全查一遍（0 死链）。有死链就修掉再说；内容还在，版本控制可回退。

> `wl/NNNN` 是纯编号引用，不受目录变化影响；这也是为什么归档/分卷不会破坏经验层的回指。

## 记录入口（元信息，**都建议、都不强制**）

两种真实写法，按容器里已有的风格选一种（也可以混写）：

**字段行式**（原型与 `comfy` 在用）：

```markdown
# 0007 · <一句话标题>

日期：YYYY-MM-DD
迭代：N                          # ← 只写一个标签；领域叫法见下
触发：<用户请求 / 缺陷 / 计划项，一句话>
范围：<改了什么、明确不做什么>
结论：<一句话结果 + 可核对的信息，如「抽样 30 条全部通过」「构建 0/0、测试 312 PASS」>
```

**引用块式**（实测 `embeding try` 在用）：

```markdown
# 2026-09-20 R21：<一句话标题>

> 状态：**已完成**／进行中／已放弃
> 工具：`<本次用到的脚本或命令>`
> 产物：`<产出的文件或数据>`
```

规则：

1. **字段名不固定，按本次情况选。** `日期 / 迭代 / 触发 / 范围 / 结论 / 来源 / 状态 / 工具 / 产物 / 环境`
   都是可认的字段名；也认英文（`Date / Trigger / Scope / Conclusion / Source / Status`）。
2. **`日期：` 是可选字段。** 日期式记录的日期在**文件名与 H1**里，两处都有就不必另写一行；
   把日期同时写到三处也不算错。真正没有任何日期（文件名、H1、入口行都没有）才算缺。
   —— 编号式容器里建议保留 `日期：`，因为文件名里没有日期。
3. **迭代行只写一个标签**。`迭代 / 变更集 / 批次 / 阶段 / 版本 / 里程碑`（英文 `Iteration / Milestone`）
   是**可互换的同义词**，都认得，但**不能写成 `迭代 / 批次：3`**——那是多个标签并排，
   只认 `标签：值`，会整行读不出来。挑你领域的那个词，其余用的时候说明一次即可。
4. **`变更集` 是可选的**，缺了不算错（实测 162 篇里 146 篇写「无」）。
5. **新记录建议写入口，旧记录不要求补。**

## 小节结构（自由）

**不规定**节次的数量、名称与顺序。唯一硬要求：

> **一个验证类小节**：标题含
> `验证 / 复核 / 检查 / 评审 / 结果 / 证据 / 评估 / 确认 / 实测 / 审查 / 实验 / 判定 / 评测`
> 之一（英文 `Verification / Review / Results / Evidence / Tests`），h2–h4 都算。

为什么松动：实测 `embeding try` 71 篇里出现了 **409 个不同的 `##` 标题**，而最高频的那个也只出现 2 次
——结构是长出来的，强行套模板只会让人绕开它。原型那套六段式（背景→事实→方案→执行→验证→遗留）
**仍然可用，但现在是「模板之一」**（见 [templates.md](templates.md)），不是必填。

## 验证段（必填）

必须留下**可核对**的东西（不必是命令——数字、百分比、引用输出、表格、样本、评审意见都算）：

```markdown
## 验证

- 方式：<命令 / 数据 / 引用 / 样本 / 评审>
- 结果：<实测输出要点 / 通过数 / 数字 / 结论>
- 未覆盖：<明说没验的部分与原因；不许写「应该没问题」>
```

**光有标题不够，只有设置也不算。** `## 评测设置` 这种标题**只交代做法**，
所以不能拿一句命令顶数：必须有实测数字/百分比、或结果表格。
已知误报风险：讲方法的散文（「方法对比」）如果标题带了设置类词又不落数字，会被报出来——
所以这一条**默认只当提醒**，不直接判不通过；真实语料上命中量很小（`comfy` 30 篇 0 命中）。

只有「构建通过」或「我觉得没问题」不算验证。软件项目给可复现命令与通过数；研究项目给样本量与数据；
写作/设计项目给评审意见与处理结果。

**这一节在任何档位下都必填**（见「记录精细度」）。另外，`digest` / `milestone` 档位下还要写明
这一轮**刻意没有记录什么**，例如：

```markdown
未记录：本轮的两处配置调整，见提交 abc1234。
```

## 台账（`work_log/README.md`，**建议但不强制**）

台账的职责是「这条线的背景与关键事实 + 导航」。实测五条线里有四条**根本没有台账文件**，
记录照样在写——所以缺台账只当提醒，不算不通过。

```markdown
# 记录 / Worklog

本文件夹用于记录 <这条线在做什么>。

## 项目背景
- 目标：
- 方案：

## 关键事实（已核实）
- <核实过的、以后会反复用到的结论>

## 文件索引
### A. <阶段名>（YYYY-MM-DD ~ ）
| 文件 | 方面 |
|---|---|
| [0001-示例.md](0001-示例.md) | <一句话> |

## 同主题簇
- **<主题>**：0007、0012 —— <一句话演进>

## 待办（滚动清单）
- [ ] <未完成项>

## 当前状态（YYYY-MM-DD）

- 阶段 / 版本：
- 迭代：
- 产出：
- 核对 / 验证：
- 交付物与指纹：
- 环境：
- 阻塞 / 等待：
- 精细度：full
```

规则：

1. **`## 当前状态` 是容器自选的**。台账里**有**它 → 核对新鲜度（日期不早于最后一篇记录）
   且全文件**只能有一个**；台账里**没有** → **不算错**。
   —— 实测 `embeding try` 把状态写在每篇开头的引用块里（`> 状态：…`），台账里根本没有状态块。
2. **没有索引表也不算错**：整份台账缺 `## 文件索引` 只是"索引层缺位"，
   这时不要逐篇去挑"未出现在索引中"。
3. 状态块只写**当前坐标**，不写历史；历史属于记录和 `STATE-HISTORY.md`。
4. `精细度` 是第八个字段：写 `full` / `session` / `digest` / `milestone`，可选附一行原因
   （见「记录精细度」）。**缺失不算错**，按默认档 `full` 处理。
5. 待办清单只留未完成项 + 最近完成的 3–5 项（`- [x]`），旧勾选项删掉，别越堆越长。
6. 索引表每行：`| [NNN-slug.md](NNN-slug.md) | 一句话方面 |`（日期式就是 `YYYY-MM-DD-slug.md`）；
   新增记录必须补一行。
7. 「同主题簇」：同一件事跨多篇时追加编号（日期式写日期或文件名），按发生顺序排。

## 渐进原则（老记录只当提醒）

新写的记录按新规格复核；**改动之前写下的记录只当提醒，不算不通过**。
否则第一次拿新规格过老项目就是一片红，人会开始忽略这份清单。

判定依据是**显式清单**，不要用日期猜（日期不可靠：同一份语料里日期字段可能只覆盖一半）。

| 来源 | 写法 |
|---|---|
| **项目里说清**（首选） | 容器根 `LEGACY.md`，每行一条：`- 0007-*` / `- archive/**`；支持 `#` 注释 |
| **这次复核口头圈定** | 当着用户说清"这次只看新记录"或"这一批算老记录" |

只有「因旧格式而不合格」的三类受影响：

| 规则 | 说的是什么 |
|---|---|
| **H1 形制** | H1 必须与文件名一致（编号式带篇号 / 日期式带日期） |
| **入口日期行** | 旧技能要求的 `日期：` 字段行 / `结论：` 为空 |
| **验证小节** | 旧技能要求的六段式里的验证小节（含"只有设置没有结果"） |

**死链、漏索引、编号重复/断档、lessons 来源**这些**从来就有**的客观问题**不受影响**，
不管是新记录还是老记录，**永远算不通过**。

## 经验层（`work_log/lessons/`）

条目格式固定为一条一行（或一小段）：

```markdown
- **<症状>**：<观察到的现象>。根因：<机制>。做法：<正确做法>。（`wl/0042`）
```

规则：

1. **每条必须有来源**（`wl/NNNN` 或外部链接）；无来源的结论不许进 lessons。
2. 只写**可复用**的结论，不复制记录里的过程与数字。
3. 分册边界清晰，按项目实际领域划分（示例：构建与环境、外部契约与接口、验证与安全、事故与流程、阶段复盘）。
4. 新增经验先写分册，再回填来源；**来源编号必须真实存在**（自己去那一篇核对）。
5. 阶段复盘（`99-retrospectives.md`）写阶段表、成果、可复用发现、遗留；**不要**在别处再写一份。

## 索引与链接

- 相对链接一律相对**当前文件**；跨目录用 `../`。
- 归档后旧链接要改指 `<stage>/`；**提交信息里的旧路径不追改**（那是历史）。
- 每次收尾自己查一遍：死链、漏索引、编号断档、无来源经验。这就是没有工具时最容易漏的四项。

## 命名与语言

- 文件名：ASCII 优先；已有中文名不强制改。标题可以中文。
- 手工新增的脚本类文件遵守仓库既有编码约定；文档一律 UTF-8。

## 手工操作规程

这一节是**没有脚本时的操作手册**。按需要跳着看，每一步都写完就停，不用记命令。

### 一、初始化容器

1. 查已有体系（见 SKILL.md 工作流 A 第 1 步）。**有就沿用，不要新建平行目录。**
2. 照 [templates.md](templates.md) 落四个文件：`work_log/README.md`（第 2 节）、`work_log/ARCHIVE.md`（第 3 节）、
   `work_log/STATE-HISTORY.md`（第 4 节）、`work_log/lessons/README.md`（第 6 节）。
3. 建 3–5 个经验分册：`work_log/lessons/01-<topic>.md` 起（第 5 节），编号两位数。
   再多一个 `99-retrospectives.md`（第 7 节；可以后补）。
4. 有持久日志的项目建 `work_log/logs/<来源>/`。**初始化时建不建都行**：
   拿不准就先不建，等第一份日志真的出现时再建，别为了占位造一个空目录。
5. 在项目根 `README.md` 加一行指向 `work_log/README.md`。
6. **自检**（初始化必须验过再往下用）：
   - 删掉台账模板里的示例索引行 `[0001-示例.md](0001-示例.md)`，以及示例待办、示例同主题簇。
   - 把每个链接点一遍，目标文件都要在。
   - 确认 `README.md`、`STATE-HISTORY.md`、`ARCHIVE.md`、`lessons/`、`logs/` 都没有被编上号。
   - 台账**有** `## 当前状态` 时：只有一个，且带日期（没有这一块不算错）。
   - 定下命名约定（编号式 / 日期式），之后**只用这一种**。
   **自检没过就别开始写记录**——带着死链往下走，后面每一篇都会复制这个错。

### 二、手工新增一篇记录

**先确认这个容器用哪种命名**（见「两种命名约定」），然后二选一：

**编号式**：

1. **先定编号**：把容器根、年份卷目录、以及**每一个阶段子目录**里的记录都看一遍，取现有记录的**最大篇号**，加一。
   编号永不复用——**曾经用过、后来归档了的号也不许再用**。
   只看容器根是不够的：归档记录在 `work_log/<stage>/` 下，那里往往存着更早、号更小的篇，别跳过。
2. **建文件**：`work_log/NNN-<slug>.md`。slug 用 ASCII 小写连字符；
   纯中文标题就用篇号当文件名（`0007.md`），标题照样写中文。
3. **写 H1**：`# NNN · <一句话标题>`——篇号必须与文件名一致。

**日期式**：

1. **建文件**：`work_log/YYYY-MM-DD-<slug>.md`，日期用今天。不分配编号。
2. **写 H1**：`# YYYY-MM-DD <一句话标题>`——日期必须与文件名一致；
   需要稳定指代时可在日期后加一个行内实验号（`# 2026-09-20 R21：标题`）。
3. 同一天可以有多篇，靠标题区分。

**两者共同的下半段**：

4. **粘记录模板**（[templates.md](templates.md) 第 1 节）——**它是模板，不是规定**：小节结构自由，
   按内容长。入口字段按需要写：日期、迭代、触发、范围、结论。迭代行**只写一个标签**。
5. **写正文**：至少要有一个**验证类小节**。不确定的先标「未核实」，并写清怎么核。
6. **验证小节必须有结果**：方式 / 结果 / 未覆盖三行，其中「结果」要给数字、百分比、命令输出或表格。
   标题是「评测设置」这类时尤其注意——**只写设置等于没写结果**。任何档位都一样。
7. **回填台账**（有台账时）：索引表加一行（写法见「四、更新台账」）。
8. **注意**：模板里那一节「六、更正」平时**不要**出现在正文里，需要时再追加（见「三、追加与更正」）。

### 三、追加、续写与更正

**同一件事跨了多次会话**：不要新开篇，追加到原来那一篇。

1. 打开当前那篇记录。
2. 在对应小节里补内容；执行表照 `| 对象 | 改动 |` 追加表行；验证小节补上新的方式与结果。
3. 更新入口的 `结论：` 那行，让它反映最终结果（有入口块时）。
4. 更新台账（索引行的「方面」如果有变，一起改）。

**推翻旧结论**：绝不抹掉原文，追加一节：

```markdown
## 更正

- YYYY-MM-DD：原结论「…」→ 新证据「…」→ 现结论「…」。
```

注意标题**不带编号**（不要写成 `## 六、更正`），这样追加第二次也不会打架。
记得同步台账与 lessons：旧结论被推翻时，引用了它的经验条目也要改。

### 四、更新台账

按顺序做，别漏最后一项：

1. **索引表加一行**。找到对应的阶段小节（`### A. <阶段名>`），在表格末尾加：
   `| [0007-slug.md](0007-slug.md) | <一句话方面> |`。
   链接写**相对台账文件**的路径（记录在容器根就是 `0007-slug.md`；已归档才写 `<stage>/0007-slug.md`）。
   没有合适的阶段小节就新建一个 `### <下一个字母>. <阶段名>`。
2. **同主题簇**：这件事和别的篇是同一主题时，在那一行追加编号，按发生顺序排。
3. **滚动待办**：加新项（`- [ ]`）、勾掉完成的（`- [x]`）；
   只留未完成项 + 最近完成的 3–5 项，旧的勾选项删掉。
4. **追加新记录时必须补索引行**，这是最容易漏的一步。漏了索引，这篇记录就等于不存在。

### 五、更新状态块 / 退休旧块

**只改字段（同一篇章没结束）**：

1. 打开台账，找到那唯一的 `## 当前状态`。
2. 改字段值。字段名用台账里已有的写法，认短名：
   写「核对」会落到「核对 / 验证」上，写「阶段」会落到「阶段 / 版本」上。
   **不要**因为它短就新建一个平行字段。
3. 把标题里的日期改成今天：`## 当前状态（YYYY-MM-DD）`。
4. 确认日期 ≥ 最后一篇记录的日期。

**退休旧块（换新状态块时）**：

1. 把旧的 `## 当前状态` 块**整段**（标题 + 8 个字段）剪下来。
2. 粘到 `work_log/STATE-HISTORY.md`，按**时间倒序**放在最上面；只搬运，不改写。
3. 回台账写一块全新的 `## 当前状态（YYYY-MM-DD）`，字段骨架照模板。
4. 确认台账里**只剩一块** `## 当前状态`。

### 六、切换精细度

1. 打开台账，找到 `## 当前状态` 里的 `精细度：` 那一行。
2. 值改成 `full` / `session` / `digest` / `milestone` 之一。只写这四个拉丁值。
3. 要留理由就写在同一个值里：`精细度：digest（原因：阶段收口）`。
4. 这一行缺失就**什么都不做**：缺 `精细度` 不算错，按默认档 `full` 处理。要补也行，补上默认值即可。
5. 临时切档（只管这一轮）不用改台账，在会话里说一句就行；但它不会留给下一次会话。

### 七、新增一条经验

1. 先判断这条经验属于哪个分册；没有合适分册就新建一个（编号顺延，`99` 留给阶段复盘）。
2. 按格式写一条：症状 → 根因 → 做法，句尾带来源。
   `- **<症状>**：<现象>。根因：<机制>。做法：<正确做法>。（`wl/0042`）`
3. **核对来源真的存在**：打开 `work_log/0042-*.md`（已归档则在 `<stage>/` 下）确认那一篇确实支持这条结论。
   日期式容器写文件名并打开那一个文件。来源写错等于没有来源。
4. 只写可复用的结论，不要把记录里的过程与数字抄一份过来。
5. 分册索引（`lessons/README.md`）新建分册时要加一行。

### 八、归档一个阶段

1. **先确认判据**：这个阶段结束了、索引表不再增长。不要用「多少天没引用」这类经验值。
2. **先搜链接**：在整个仓库里搜要归档的篇号与文件名，把命中位置列出来。
   至少包括：台账索引表、`lessons/` 各分册、其它记录正文、项目根文档。
3. **建阶段目录**：`work_log/<stage>/`（直接建在容器下，**没有** `archive/` 一层）。
4. **移动文件**：把篇号区间（或日期区间）的记录移进阶段目录。**编号不变，内容不改。**
5. **改写链接**：把第 2 步列出的每一处链接改成新路径（`0007-x.md` → `<stage>/0007-x.md`）。
   被移动记录**自己的出站链接**也要看一遍：指向同批被移动记录的链接同样要改。
6. **补归档索引**：在 `ARCHIVE.md` 的表格里加一行（目录 / 篇号 / 时间 / 内容 / 归档判据）；
   日期式容器把「篇号」一列写成日期区间。
7. **死链自检**：重新搜一遍链接，逐个确认目标文件存在。0 死链才算做完。
8. **索引瘦身**（可选，紧跟着做）：整节都已归档的索引小节折叠成一行区间
   `| [<stage>/](<stage>/) | 0027–0045（19 篇，已归档） |`。
   混合小节、含死链的小节、非记录行、已折叠过的行都不要动。
9. 提交信息里的旧路径**不追改**（那是历史）。

### 九、冷存（很久以后）

1. **第一步永远只是报告**：列出候选 = 已归档 + 未被 lessons 引用 + 足够久（经验值 180 天以上）。
   把清单给人看，等明确要求。
2. 得到明确要求后：打包、留清单（`COLD-STORE.md` 或归档索引里的说明）、再把原件移出。
3. **绝不删除。** 未被引用 ≠ 没价值。真要删由人自己动手。

### 十、接管一个已有体系

1. 先读，不要先动：容器是谁、叫什么名、**用的哪种命名**、编号到哪（或最早/最晚日期）、
   索引什么结构、lessons 怎么分册。
2. 沿用它的命名与编号。旧名 `journal/`、`work-log/`、顶层 `lessons/` **只读取、不迁移**。
3. 只有用户明确要求时才改名或迁移；迁移是独立一件事，值得单独一篇记录。
4. **接手时先分清哪些是老记录**，写进 `LEGACY.md`（见「渐进原则」）：
   老记录只当提醒，别一上手就拿新规格把它们全判不通过。

### 十一、手工复核清单

这是**代替门禁**的那一步：收口前逐条走。任何一条不通过就算**不通过**，不要当提醒放过去。
**老记录除外**（见「渐进原则」：只有 H1 形制 / 入口日期行 / 验证小节这三类可以被当成提醒）。

**结构（原 `check` 的职责）**

- [ ] 文件名是两种命名约定之一；两种都不是的文件**不是记录**，跳过即可
- [ ] 每篇标题与文件名一致：编号式 `# NNN · 标题`、日期式 `# YYYY-MM-DD 标题`
- [ ] **编号式容器**：编号连续、不重复，没有断档
- [ ] 日期在任何一处有就行（文件名 / H1 / `日期：` 行）；三处都没有才算缺
- [ ] 每篇都有验证小节（标题含那组别名之一，h2–h4 都算）
- [ ] 全库 md 链接无死链
- [ ] 有索引表时，活跃记录都在里面（没有漏索引）
- [ ] 台账**有** `## 当前状态` 时：只有一个、带日期，且日期不早于最后一篇记录
- [ ] 每条 lessons 的来源都指向真实存在的记录

**内容（原 `lint` 的职责）**

- [ ] 没有模板占位符残留（`<一句话>`、`<对象>`、`TODO` 等）
- [ ] 没有空小节（标题在、下面空着）
- [ ] `结论：` 里有可核对的信息（数字、通过数、引用），不是「已完成」
- [ ] 验证小节里有可核对的内容（数字 / 百分比 / 命令 / 引用输出 / 表格），不是「应该没问题」
- [ ] 标题是「设置 / 目的 / 方法」这类时，正文里有**结果**（数字或表格），不是只有做法
- [ ] `digest` / `milestone` 的记录里写了「未记录：…」

**门禁档与提醒档的区别**

- 默认档下，缺日期、缺验证小节、漏索引、状态块没日期都只是**提醒**，不算不通过。
- **按门禁标准复核时，上面每一条都算不通过**（老记录的三类除外，见「渐进原则」）。
  自己盯住**标题与文件名一致**、**验证小节有结果**这两条，它们最容易漏。
