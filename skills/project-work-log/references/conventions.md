# 约定（Conventions）

> 这些是硬约定。`journal.py check` 按本文件实现校验；偏离前先想清楚代价，偏离后要在记录里写明。

## 目录布局

```
<项目根>/
├── journal/
│   ├── README.md             ← 唯一台账：索引表 + 同主题簇 + 滚动待办 + 当前状态
│   ├── 0001-<slug>.md        ← 过程记录，一篇 = 一个迭代（一个可交付的工作单元）
│   ├── 0002-<slug>.md
│   └── archive/
│       ├── README.md         ← 归档索引 + 编号换算（归档不改号）
│       ├── STATUS-HISTORY.md ← 被替换下来的旧「当前状态」块
│       └── <stage>/NNNN-*.md
└── lessons/
    ├── README.md             ← 分册索引 + 使用方式
    ├── 01-<topic>.md
    ├── ...
    └── 99-retrospectives.md  ← 阶段复盘（承接 SUMMARY 的职责）
```

- 目录名可用 `journal/`，也允许沿用既有名字（如 `work-log/`）。**只看行为，不强制改名。**
- 记录文件名：`NNNN-kebab-or-中文扼要.md`，编号 4 位（历史文件早已是 1–3 位则不要重命名）。
- 编号**单调递增、永不复用**，归档不改号。

## 两个计数器（不要混）

| 名字 | 含义 | 在哪 | 规则 |
|---|---|---|---|
| **篇号** | 记录文件编号，索引与回指的地址 | 文件名 + 标题 `# 0007 · ...` | 每写一篇 +1；永不复用；跨归档不变 |
| **迭代号** | 项目层面的工作单元编号（一个可交付的迭代） | 记录入口的迭代字段（默认 `迭代: N`） | 一个迭代可以对应多篇（如"执行 + 验收修复"）；一次性/不编号的工作写 `迭代: -` |

回指统一写 `wl/NNNN`（篇号），不要写"迭代 N"，否则两者会混淆。

**迭代字段的别名**（解析时都认，写入时用默认的 `迭代：`）：`迭代 / 变更集 / 批次 / 阶段 / 版本 / 里程碑`。
不同领域用不同叫法：软件用「变更集/版本」，研究用「批次/阶段」，写作/设计可能用「里程碑」。

## 记录生命周期

```
草稿（进行中）  →  收口（closed）  →  （可选）归档
```

- **草稿**：标题下方元数据可边做边补；允许写"未验证/待确认"。
- **收口**：收尾清单（见 SKILL.md）全部完成后才算 closed。收口后**不改写已发生的结论**。
- **更正**：新证据推翻旧结论时，**追加** `## 更正` 段（日期 / 原结论 / 新证据 / 现结论），并同步台账与 lessons；
  绝不允许把旧文字直接抹掉。
- **归档**：阶段收口、索引表停止增长时，把整阶段的记录 move 到 `journal/archive/<stage>/`；
  同步改索引链接、写归档索引，并跑一次 `journal.py check`。

## 整理与清理（量增长后）

**证据不删**是硬规则：清理 = 移走 + 汇总 + 留清单，不是删除。

| 动作 | 命令 | 说明 |
|---|---|---|
| 阶段归档 | `journal.py archive --stage X --from N --to M` | 移动 + 全仓链接重写 + 补 `archive/README.md` + 死链自检 |
| 索引瘦身 | `journal.py index compact` | 已归档小节折叠成一行区间；混合/死链小节自动跳过 |
| 按年分卷 | `journal.py split --by-year` | 移进 `journal/<YYYY>/`；`wl/NNNN` 回指不受影响 |
| 冷存 | `journal.py prune [--zip Z] [--apply]` | 默认只报告；打包后才移出，并写 `archive/COLD-STORE.md` |

判据与顺序：

1. **归档判据 = 阶段收口**（索引表不再增长），不用"多少天没引用"这类经验值。
2. 归档后立刻 `index compact`：否则索引会随归档线性膨胀（实测每篇约 600 字符）。
3. 冷存判据：已归档 + **未被 lessons 引用** + 早于 `--older-than`（默认 180 天）。
   未被引用 ≠ 没价值，所以 `prune` **默认只报告**，要人确认后才 `--apply`。
4. 搬家后必跑 `check`（0 死链）；有死链就报错退出（内容还在，git 可回退）。

> `wl/NNNN` 是纯编号引用，不受目录变化影响；这也是为什么归档/分卷不会破坏经验层的回指。

## 记录入口（Front-matter，固定 5 行 + 1 可选）

```markdown
# 0007 · <一句话标题>

日期：YYYY-MM-DD
迭代：N                          # ← 只写一个标签；领域叫法见下
触发：<用户请求 / 缺陷 / 计划项，一句话>
范围：<改了什么、明确不做什么>
结论：<一句话结果 + 可核对的信息，如「抽样 30 条全部通过」「构建 0/0、测试 312 PASS」>
```

- **迭代行只写一个标签**。`迭代 / 变更集 / 批次 / 阶段 / 版本 / 里程碑`（英文 `Iteration / Milestone`）
  是**可互换的同义词**，解析时认全部，但**不能写成 `迭代 / 批次：3`**——那是多个标签并排，
  解析器只认 `标签：值`，会整行读不出来。挑你领域的那个词，其余用的时候说明一次即可。
- 可选的**第 6 行**是 `来源：`（英文 `Source`），用于复现型/研究型记录标明数据或样本出处。
- `日期：` **必填**。注意默认档位下缺日期、缺验证小节只判 **WARN**；
  要当门禁用必须加 `--strict`（详见 `commands.md` 的「退出码与档位」）。
- 正文至少要有**验证/复核小节**（标题含 `验证 / 复核 / 检查 / 评审 / 结果 / 证据 / 评估 / 确认 / 实测 / 审查`
  任一即可，标题级别 h2–h4 都认）；建议含背景、方案、执行、验证、遗留五段。

## 验证段（必填）

必须留下**可核对**的东西（不必是命令——数据、引用、样本、评审意见都算）：

```markdown
## 验证

- 方式：<命令 / 数据 / 引用 / 样本 / 评审>
- 结果：<实测输出要点 / 通过数 / 数字 / 结论>
- 未覆盖：<明说没验的部分与原因；不许写"应该没问题">
```

只有"构建通过"或"我觉得没问题"不算验证。软件项目给可复现命令与通过数；研究项目给样本量与数据；
写作/设计项目给评审意见与处理结果。

## 台账（`journal/README.md`）

只有一个状态区块，字段固定：

```markdown
## 当前状态（YYYY-MM-DD）

- 阶段 / 版本：
- 迭代：
- 产出：
- 核对 / 验证：
- 交付物与指纹：
- 环境：
- 阻塞 / 等待：
```

规则：

1. **唯一性**：全文件只能有一个 `## 当前状态`。新增前把旧块整段剪到 `journal/archive/STATUS-HISTORY.md`。
2. **新鲜度**：日期必须 ≥ 最后一篇记录的日期；否则 `check` 警告。
3. 状态块只写**当前坐标**，不写历史；历史属于记录和 STATUS-HISTORY。
4. 待办清单只留未完成项 + 最近完成的 3–5 项（`- [x]`），旧勾选项删掉，别越堆越长。
5. 索引表每行：`| [NNNN-slug.md](NNNN-slug.md) | 一句话方面 |`；新增记录必须补一行。
6. 「同主题簇」：同一件事跨多篇时追加编号，按发生顺序排。

## 经验层（`lessons/`）

条目格式固定为一条一行（或一小段）：

```markdown
- **<症状>**：<观察到的现象>。根因：<机制>。做法：<正确做法>。（`wl/0042`）
```

规则：

1. **每条必须有来源**（`wl/NNNN` 或外部链接）；无来源的结论不许进 lessons。
2. 只写**可复用**的结论，不复制记录里的过程与数字。
3. 分册边界清晰，按项目实际领域划分（示例：构建与环境、外部契约与接口、验证与安全、事故与流程、阶段复盘）。
4. 新增经验先写分册，再回填来源；来源编号必须真实存在（`check` 会校验）。
5. 阶段复盘（`99-retrospectives.md`）写阶段表、成果、可复用发现、遗留；**不要**在别处再写一份。

## 索引与链接

- 相对链接一律相对**当前文件**；跨目录用 `../`。
- 归档后旧链接要改指 `archive/<stage>/`；**git 提交信息里的旧路径不追改**（那是历史）。
- 每次收尾跑 `journal.py check`：死链、漏索引、编号断档、无来源经验都会报出来。

## 命名与语言

- 文件名：ASCII 优先；已有中文名不强制改。标题可以中文。
- 脚本类新增文件遵守仓库既有编码约定（例如本工作区要求 `.ps1` 纯 ASCII）；Python/JS 用 UTF-8。
