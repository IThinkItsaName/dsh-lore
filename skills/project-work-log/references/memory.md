# 全局记忆（跨工作区，`$DSH_HOME/memory/`）

> 这一层把工作区的**经验层**延伸到工作区之外：让一个工作区里确证过的教训，
> 能在**另一个**工作区被用到；让与工作区无关的通用知识也有处可放，且**不冒充已验证**。
>
> 命令语法见 [commands.md](commands.md) 的「全局记忆／收敛／信箱／升格」。

## 零、为什么放在 `$DSH_HOME` 下

落在 `<DSH_HOME>/memory/`，与 worklog 插件目录**平级**，不放进插件自己的目录。

| 理由 | 说明 |
|---|---|
| 记忆是**跨插件的公共知识** | 不该锁在一个插件的私有柜子里；将来别的东西要读它，不该先学 worklog 的内部布局 |
| **卸载不该带走记忆** | 卸掉 worklog 插件，记忆应当留着 |
| 与既有约定一致 | 宿主的 `profiles/`、`sessions/`、以及各插件的 `<DSH_HOME>/<名字>/` 都在这里 |

**落点的三级覆盖**：`--memory <P>` > `$DSH_WORKLOG_MEMORY` > `$DSH_HOME/memory`
（`$DSH_HOME` 没设时是 `~/.dsh`）。

环境变量那一档是为**测试隔离**留的：harness 必须能指向临时目录，否则跑一次测试
就会动到用户真实的记忆库。这条坑本项目在设置文件上已经踩过一次，所以自测里
**每一条记忆命令都带 `--memory`**。

## 一、分层

| 层 | 位置 | 进注入？ | 谁读 |
|---|---|---|---|
| 工作区记录 | `<工作区>/<容器>/` | 否 | 智能体（工作区内文件工具） |
| 工作区经验 | `<工作区>/<容器>/lessons/` | 否 | 智能体 |
| 发布清单 | `<工作区>/<容器>/发布.md` | 否 | 全局层工具（**唯一**获准读的工作区文件） |
| 项目摘要 | `<工作区>/<容器>/摘要.md`（`dream` 产出） | 否 | 智能体 |
| **全局记忆** | `<DSH_HOME>/memory/` | 只注入索引一笔 | **只能通过工具** |
| 常驻规则 | 根 `AGENTS.md` | 是 | 宿主 |

**为什么智能体不能用文件工具读全局记忆**：工作区文件工具被硬限制在工作区内；
而注册进宿主的工具**在宿主进程内执行**，能读 `$DSH_HOME`。所以记忆只能经**工具**访问。
这不是设计偏好，是唯一的通路。

**工具也没有跨工作区读文件的权限**，这一条决定了下面三件事的做法：

1. 工作区**无法自动发现** —— 只能靠它自己 `memory publish` 时登记；沉默 = 不参与。
2. 「来源真实存在」在别的工作区里**只能靠发布清单核**（那是唯一获准读的文件）。
3. 发布清单因此天然成了**双向白名单**：不在清单里的教训，永远不会离开那个工作区。

## 二、目录布局

```
<DSH_HOME>/memory/
├── .gitignore               排除 personal/ 与 inbox/
├── INDEX.md                 注入用索引（**生成物，不手写**）
├── workspaces.json          名册：路径 / applies-to / read / upload / 最后发布
├── candidates.json          候选：知存在、未登记（**只提示，不自动收录**）
├── .state.json              机器生成：各工作区清单的摘要哈希 + 检索命中计数
├── 01-<领域>.md             正文分册
├── personal/                个人内容：不进 git、不进索引、不被默认检索
└── inbox/                   跨工作区信箱：不进 git，阅后即删或转移
```

**为什么统一一个根**：检索、索引生成、lint 只需遍历一处；「不进 git」用
`.gitignore` 精确表达即可，不必开平行顶层目录。

**为什么必须进 git**：`$DSH_HOME` 不被任何东西同步，删一次就没了；而「能 `git diff`」
正是**你审阅「谁想进来」**的机制 —— 那是唯一可能造成污染的动作。

**分册的判据**：`<记忆根>/NN-<领域>.md`（`personal/` 下同形，`NN` 一两位）。
`INDEX.md`、名册、候选、状态的形状都对不上，所以不必逐个排除。

**`personal/` 与「一条事实只有一个家」不冲突**：那里放的是**另一类**内容，
不是同一条内容的副本。

## 三、条目格式

正文分册里**一条一段**：

```
- id: <slug>
  applies-to: <标签, 标签>
  state: active | stale | retired
  source: <来源分档>
  cited-by: [<工作区>, …]        ← 生成，不手写
  <一句话教训：症状 → 根因 → 做法>
```

字段规则：

| 字段 | 规则 |
|---|---|
| `id` | **全局唯一**，只认 `[a-z0-9][a-z0-9-]*`（小写拉丁 / 数字 / 连字符）。不带空格、不带大写 |
| `applies-to` | 逗号分隔的标签，同样只认小写拉丁 / 数字 / 连字符。**留空表示「到处都适用」** |
| `state` | 三态之一，缺省 `active` |
| `source` | 见 §四。认不出 = 拒绝 |
| `cited-by` | 由工具维护，手写不算数 |
| 正文 | 一行。`症状 → 根因 → 做法` 的形状最好用，但不强制 |

**字段解析只认那五个名字**：正文里写一个 `做法：…` 不会被误当成字段。
代价写在明处：**正文别以 `id` / `applies-to` / `state` / `source` / `cited-by` 开头**。

**标签为什么只认一种写法**：标签会被**跨工作区取交集**。`Dsh-Plugin` 与 `dsh-plugin`
是两个标签还是一回事，机器判不出来；要求一种写法，交集就是确定的。

## 四、来源分档（准入的核心）

**准入靠分档，不靠「看起来重要吗」** —— 后者等于预测未来，而且会系统性地偏向
「听起来宏大的话」，正好与实战教训相反。

| `source` | 准入 | 进索引 | 附加要求（`lint` 判） |
|---|---|---|---|
| `wl/NNNN` | 允许 | 是 | 该篇号必须**真实存在**（机械校验） |
| `<工作区>/wl/NNNN` | 允许 | 是 | 那个工作区的**发布清单**必须点名 `wl/NNNN` |
| `manual:tested` | 允许 | 是 | 正文须写清**怎么验的**（命令 / 数字 / 结果） |
| `manual:read` | 允许 | 是 | 正文须**指名出处**（哪个文件、哪一节） |
| `manual:inferred` | **允许** | **否** | **强制标注「未经证实」** |
| 无 / 认不出 | **拒绝** | — | — |

**日期式容器**把记录名当引用：`wl/NNNN` 的位置写文件名（`2026-09-06-门控两段式.md`），
判据同样是「真实存在」/「清单点名」。

> **为什么留 `inferred` 一档而不是堵死**：堵死的结果不是「没有推断」，
> 而是**推断被伪装成「读过」**。留一档并强制标注，比如下更安全 ——
> 这与本项目「错误的机制比没有机制更糟」的既有判断一致。

**两档附加要求的判据是保守的**（宁可漏，不可误报 —— 误报会教人忽略告警）：

- `manual:read` 只要求正文里有**一个**出处线索：反引号里的名字、`a/b.ext` 形状的路径、或 `§`。
  刻意**不**认「第 N 节」这类泛泛说法 —— 它在中文里几乎每句都有，等于没判。
- `manual:tested` 只要求正文里有反引号**或**数字。

## 五、发布清单（`<工作区>/<容器>/发布.md`）

工作区**唯一**获准被全局层读取的文件，也是**双向白名单**：不在清单里的教训
永远不会离开那个工作区。

```
applies-to: dsh-plugin, python-stdlib-tooling
upload: true

# 注释行以 # 开头，解析时跳过。

- wl/0001  样式被别的插件认领  →  id: host-style-claiming
```

| 部分 | 含义 |
|---|---|
| 头两行 | **本工作区的声明**：它关心哪些标签（供注入取交集）、是否允许上传 |
| 条目行 | 点名「哪条教训允许外流」，可给一个建议 id |

- `upload: false` 或**缺清单** → 视为**只读不传**（合法且常见的默认）。
- 没写 `→ id:` 时按引用机械兜底：`wl/0001` → `wl-0001`。想要一个能读的 id 就显式写。
- **每一行那句话就是它进全局记忆后的正文**（全局层读不到别的文件）。所以它得自己
  站得住，不能靠「点进去看」。
- 清单里**不要写工作区前缀**（`ws/wl/0001`）：它就是本工作区自己的出口，加了前缀反而认不出。

`memory publish` 生成的是**草稿**：从经验层挑出所有带 `wl/NNNN` 引用的条目，
把它们的一句话直接抄过来。人再把它改成**能带走**的措辞。再跑一次 publish
**不会冲掉手改过的 id**。

## 六、注入（两套接口，按易变性分工）

| 内容 | 接口 | 理由 |
|---|---|---|
| 全局记忆索引 | `ctx.systemPrompt.section({…})` | 稳定；进系统提示词当固定前缀 |
| **待收 N 条** | `ctx.systemPrompt.context({…})` | **可变；尾注入**（计数为 0 时返回空串，零快照） |

- 两处的 `text` 都用**函数形式**（每次装配求值）→ 相应设置项**改完立即生效**。
- **预算按字计不按行计**：一行的长度可以差十倍，按行限等于没限。
  软目标 `MEMORY_INDEX_SOFT_CHARS`（提示该收敛），硬上限 `MEMORY_INDEX_HARD_CHARS`。
  **超限报错，绝不静默截断** —— 静默截断会让记忆悄悄变得不完整。
- 索引是**生成物**：`memory index` 重建，`memory index --check` 只校验。
  手写的索引与正文一定会分叉，而 `lint` 会把它当 ERROR 报出来。

## 七、生命周期与长期价值

**入场时不判断「长期价值」** —— 那等于预测未来。入场只做两件机械事：
来源分档合法 + 发布清单点名。

| 事后信号 | 价值 | 动作 |
|---|---|---|
| **被别的工作区引用** | **最强且无法伪造** —— 它真的跨了工作区 | 排序**前置**；累计进 `cited-by` |
| **被修订（记下「被什么取代」）** | 冲突已消化，信息密度更高 | **唯一自动降级**：`active → stale` |
| 被检索命中 | **弱且危险** | 只用于 `lint` **建议**审阅，**绝不自动降级** |

> **只会在极罕见情况下救命的教训，命中次数天然是 0，而它可能最珍贵。**
> 用命中次数降级会系统性删掉最珍贵的保险、留下最常被问的常识。

**三态**：`active`（进索引）/ `stale`（不进索引，仍可搜）/ `retired`（默认搜不到，
**文件永不删**）。降级要人显式改 `state` —— 工具不做价值判断。

**成长压力在索引，不在条目数**：索引大小 ≈ 相关领域数 × 每领域条数，与总条目数
**非线性**。所以只解决「索引可扫读」，**不对总条目数设上限**。

**`cited-by` 与同名 id 的关系**（这一条要看清，它决定了「引用」怎么发生）：

- 同名 id 落在**同一个分册（同一个领域）** → 说的是同一条教训，第二个工作区是在
  **引用**它 → 累计进 `cited-by`。
- 同名 id 落在**别的分册（别的领域）** → **冲突**，拒绝收集
  （「两个工作区发布同名 id 会被拒绝」）。

判据是分册，因为「同一个领域里叫同一个 id」才说明它们说的是同一件事。

## 八、校验（`memory lint` / `memory index --check`）

| 判据 | 级别 |
|---|---|
| 来源合法且可分档；`wl/NNNN` 能指到真实记录（或清单点名） | ERROR |
| `manual:read` 未指名出处 / `manual:tested` 无可核对结果 / `manual:inferred` 未标注「未经证实」 | ERROR |
| `manual:inferred` **不得出现在索引**中 | ERROR |
| `id` 不合法或重复；`applies-to` 标签非法；`state` 认不出 | ERROR |
| `cited-by` 引用的名字不是名册里已登记的工作区 | ERROR |
| 索引与正文一致（漏生成 / 多出条目） | ERROR |
| 注入段超**硬上限** | ERROR |
| 分册标题与文件名里的领域对不上 | WARN |
| 近似重复（正文规范化 + trigram Dice 过阈） | WARN（`--strict` 才 ERROR） |
| 长期未命中 / 够条件可升格 | INFO（仅建议） |

沿用本项目既有的「启发式不判死刑」规矩：**判不准的一律 WARN，`--strict` 才 ERROR**。

**两个「不校验」，是刻意的**：

- **不校验工作区目录是否还在** —— 那是 `memory status` 的活（名册那一行会打 `!`）。
  `lint` 只管记忆本身。
- **不用命中次数做任何判断以外的动作** —— 它只出现在 INFO 里。

## 九、名册与许可

| 规则 | 说明 |
|---|---|
| `read` 默认 `true`、`upload` 默认 `false` | 「只看不给」合法且常见 |
| 未登记的工作区 | **不参与**。工具**无法自行发现工作区**，所以沉默 = 不参与 |
| `candidates.json` | **只提示**（`memory status` 报「有 N 个候选未登记」），**不自动收录** |
| 名册隔离 | 设置页的状态块只显示计数，不列路径；CLI 默认也只列**目录名**（`--verbose` 才给路径） |

**候选是怎么来的**：工具没有跨工作区读文件的权限，所以候选只来自
「**有人把它指给我们看**」—— 即命令行上给的那个 `ROOT`，它有清单但不在名册里。
`memory publish` 登记之后，候选里就不再有它。

**名册里的 `upload` 跟着清单走**：清单是声明（手改的也算数），名册只是它的缓存。
不跟，`memory status` 就会报一个与清单不符的值 —— 同一件事两个答案。

**同名工作区的代价写在明处**：`cited-by` 与 `--source` 只写目录名，所以两个不同路径
的工作区同名时无法区分。`lint` 为此报一条 WARN，而不是假装能分辨。

## 十、`collect` 是幂等的

`.state.json` 记着每个工作区清单的**内容摘要**：

- 清单没变 → 跳过（第二次 `collect` 一个字节都不写，连 `.state.json` 都不动）。
- 清单变了 → 只做两件事：**新增**还没见过的 id；给已存在的 id **累计 `cited-by`**。

**已存在的条目不会被覆盖**：`state`、`applies-to`、正文都是人维护的，
收集不该把它们冲掉。要改一条，就改分册里的那一条。

`collect` **不重建索引**（索引是生成物，由 `memory index` 重建），但它会在收了新东西
之后提醒一句。

## 十一、收敛（`dream`）

**摘要不是新事实**，是一条指向记录的收敛视图：每条断言都必须能下钻一层到来源。

### 两半分工（这是重点）

| 谁 | 做什么 |
|---|---|
| **脚本** | 挑出还没收敛的记录、按主题分组、发骨架、**校验每条断言的回指**、写回、标记已收敛 |
| **模型／人** | 读骨架、写总结，把 `- …（回指：<记录文件名>）` 换成断言 + 指向记录的链接 |

插件自己的节点半边**不能调用 LLM**，所以收敛必须这么切：脚本只做机械的那半，
总结那半交给模型。

### 三个模式

| 命令 | 做什么 |
|---|---|
| `dream [ROOT]` | **发骨架**：读 `摘要.md` 的覆盖范围，挑出还没收敛的记录，按主题分组，写 `<容器>/摘要.draft.md` |
| `dream --accept [ROOT]` | **收下**：校验 `摘要.draft.md` 的回指，全过才写回 `<容器>/摘要.md` |
| `dream --check [ROOT]` | **复查**：以后验证已写回的摘要（回指还指得到吗） |

- 填充好的骨架**不会被默认覆盖**（`--force` 才重发），避免把写好的总结冲掉。
- `--accept` 生成 `## 覆盖范围` 那一节（列出已收敛的记录链接）—— 它就是**「标记已处理」**，
  下次 `dream` 靠它算还没收敛的部分。要改内容就改骨架再收一次。

### 回指是机械校验的

`--accept` / `--check` 逐条判：

1. `### 主题` 下每条 `- ` 断言都必须带一个指向**记录**的 markdown 链接；
2. 占位符 `<记录文件名>` 还在 → 拒绝；
3. 每个 `### 主题` 至少要有一条断言（否则那个主题等于没收敛）；
4. 链接**复用既有的死链检查器**（与 `check` 用的是同一条路径）—— 记录被删、
   改了名、归档搬了家，这里立刻变红。

所以 **`dream` 的成品是一份「会烂的」文档**：来源记录一消失，`dream --check` 就报出来。
这不是缺陷，是它作为「指向记录的视图」的应有行为。

**主题分组的机械与代价**：用的是与 `topics` 同一套标识符共现（ASCII token + 停用词），
每条记录只进一个组。中文标题里没有 ASCII 标识符时**落单成组** —— 这是已知代价，
所以分组只是**骨架的建议**，人可以合并。

## 十二、信箱（`inbox/`）—— 它不是记忆，是通信

**不进索引、不进注入、不进 git**；阅后即删，或转移成一篇记录。

| 性质 | 做法 |
|---|---|
| 原子写 | 先写带 pid 的临时名，再 `rename`。两个工作区同时投不会互相截断 |
| 读者侧 | 读到 `.tmp` 半截文件时**当它不存在** |
| 写满 | **报错并拒绝**，不静默堆积 |

**硬上限（写满就报错）**：

| 上限 | 值 | 为什么是这个数 |
|---|---|---|
| 条数 | 200 | 一次会话塞进去的零散消息通常个位数；200 条足够「几天没看」 |
| 单条字节 | 16 KiB | 够放一段命令输出或一份差异，又不至于把一条消息变成文件传输 |
| 总量字节 | 256 KiB | 任何编辑器、一次模型注入都能吞下；超了说明该 sweep 了 |

真要大块传文件，应该进工作区、进记录，而不是走后门进信箱。

**上限是「防呆」不是「互斥」**：两个进程同时投时都可能通过检查。这是刻意的 ——
信箱不是并发安全的数据结构，上限是防它无限膨胀的护栏。

**`inbox count` 是给插件调用的**：stdout **第一行就是一个整数**，别的什么都不打印。
宿主的「待收 N 条」那条尾注入每次装配都要求值，所以这个命令必须便宜、且输出可机械解析 ——
多一行字，调用方就要开始猜。

**`take --into-record <标题>`** 会把原文**原样**搬进工作区的一篇记录（只统一换行），
并标明来自信箱哪一条，然后删掉原件。是否转移由人决定；不转移就是阅后即删。

## 十三、升格为技能（`promote`）

**分界**：一条事实进记忆；**一套过程**进技能。全局技能落在 `<DSH_HOME>/skills/`
（已被 `dsh-skill-filesystem` 的 `dshHome` 扫描覆盖，**不需要发明机制**）。

三条件**同时**满足才够格。`promote suggest` **只报候选，不自动打包**。

| 条件 | 判据 | 怎么机械判 |
|---|---|---|
| 是一套过程 | 有触发条件 + 步骤 + 验证方式，读者能照着做 | **措辞代理**：正文里同时出现触发词、步骤词、验证词 |
| 已真实执行过 | 至少一个工作区里按它做过并成功 | `source` 是 `manual:tested` 或记录来源（`wl/NNNN` / `<工作区>/wl/NNNN`） |
| 有重复需求 | 被多个工作区引用，或同一工作区多次命中 | `cited-by ≥ 2` 或 命中次数 `≥ 2` |

第 1 条判定不了，只好用措辞代理。**代理会漏报，这正是可接受的失效方向**：
`promote` 只给建议，漏报不会造成破坏；而**猜错**会让人去打包一份不合格的技能。
`promote suggest --all` 会连未够格的也列出来，并写明缺哪一条。

### 唯一硬规则 —— 技能只许「教」，不许「管」

- 可以写「这类问题怎么诊断」（教）
- 不许写「你必须先做 X」（管）

理由不只是谦虚：**一份强势的技能会与实际项目冲突，而冲突的结果通常是技能被无视
或被关掉** —— 连带它本来有用的部分一起废掉。

### 验收：必须带可跑自测

升格时同时交一个最简验证（fixture + 一条命令），且该自测**能变红能变绿**。
依据是本工作区的既有事实：技能自测把技能从「一份看起来对的文档」变成「能验的东西」；
而技能的暴露面（名字 + 描述进每个会话目录）是这些产物里最大的，坏了没人知道代价最高。
