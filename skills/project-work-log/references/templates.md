# 模板（复制即用）

> 占位符：`<项目>`、`<阶段>`、`NNN`（篇号）、`YYYY-MM-DD`、`N`（迭代号）。
> 目录一律写成默认容器名 `work_log/`（容器名可配置，见 [conventions.md](conventions.md)「目录布局」）。
> `journal.py new` 用「记录模板」自动生成文件（**编号式**；一~五节是从前的必填结构，现在是可选骨架）；
> 其余模板在初始化项目时手工落盘一次。
> `## 六、更正` 不在自动生成的正文里——它由 `append --section 更正` 在需要时追加（标题不带编号）。

## 0. 先选命名约定（一个容器只用一种）

| 约定 | 文件名 | H1 |
|---|---|---|
| **编号式** | `NNN-<slug>.md`（纯中文标题可用 `NNN.md`；也允许 4 位） | `# NNN · <一句话标题>` |
| **日期式** | `YYYY-MM-DD-<slug>.md` | `# YYYY-MM-DD <一句话标题>`（日期后可接行内实验号 `R21：`） |

- 两种都要求 **H1 与文件名一致**；**两种都不匹配的文件不是记录**，工具会忽略它。
- 编号式：编号**单调递增、永不复用、归档不改号**；回指写 `wl/NNN`。
- 日期式：不分配编号，同一天可以多篇（实测最多一天 8 篇），靠标题区分；回指写文件名。
- 一个容器内**建议只用一种**（混用会让排序与索引变乱）；混用不报错，只提示一句。

## 1. 记录模板（`work_log/NNN-slug.md` 或 `work_log/YYYY-MM-DD-slug.md`）

**下面这五节是从前的必填结构，现在是「模板之一」。** 小节结构自由：唯一的硬要求是**一个验证类小节**，
而且它必须有可核对的结果（数字 / 百分比 / 命令输出 / 表格），只写设置不算。

```markdown
# NNN · <一句话标题>                       ← 编号式；日期式写 `# YYYY-MM-DD 一句话标题`

日期：YYYY-MM-DD
迭代：N
触发：<为什么做这件事；用户请求 / 缺陷 / 计划项>
范围：<改了哪些文件或模块；明确不做什么>
结论：<一句话结果 + 关键数字>

---

## 一、背景与事实核查

<只写核实过的事实：命令、文件、输出、版本号。不确定的标「未核实」并说明怎么核。>

## 二、方案与取舍

<选项 A / B、代价对比、用户拍板的结论；没有选项时写清为什么只有这一条路。>

## 三、执行

| 对象 | 改动 |
|---|---|
| `<对象>` | <一句话> |

## 四、验证

- 方式：`<命令 / 数据 / 引用 / 样本>`
- 结果：<通过数 / 数字 / 百分比 / 关键输出——**这一行不能空**，只写"设置"不算验证>
- 未覆盖：<没验的部分与原因>

## 五、遗留与下一步

- [ ] <未完成项，交给谁 / 什么条件下做>

## 六、更正（仅在推翻旧结论时追加，平时删掉本节）

- YYYY-MM-DD：原结论「…」→ 新证据「…」→ 现结论「…」。
```

> **入口字段都可选。** `日期：` 在日期式容器里可以不写（日期已在文件名与 H1 上）；
> `迭代：` 可省；`变更集` 只是迭代字段的一个别名，写「无」或干脆不写都不算错。
> 引用块式入口（`> 状态：… ｜ 工具：… ｜ 产物：…`）同样是合法写法，见 conventions.md「记录入口」。

> **日期式的最小记录**（没有六段式、没有 `日期：` 行，照样过门禁）：

```markdown
# 2026-09-06 门控两段式

> 状态：**已完成** ｜ 工具：`mini_bert.py` ｜ 产物：`exp/gate_10k.json`

## 设置

MLM 10k → sim NCE 5k，4×256×8。

## 结果

| 项 | ρ |
|---|---|
| 门控两段式 | 0.4973 |
| 门控从头 | 0.5049 |
```

## 2. 台账模板（`work_log/README.md`）

```markdown
# <项目> 工作记录

> 可复用的坑/技巧/教训见 [`lessons/`](lessons/README.md)；本目录只放逐个可交付单元的过程记录。

## 项目背景
- 目标：
- 方案：

## 关键事实（已核实）
- <核实过的、以后会反复用到的结论>

## 文件索引

### A. <阶段名>（YYYY-MM-DD ~ ）

| 文件 | 方面 |
|---|---|
| [0001-示例.md](0001-示例.md) | <一句话> |

## 同主题簇

- **<主题>**：0001、0002 —— <一句话演进>

## 待办（滚动清单）

- [ ] <未完成项>
- [x] <最近完成的 3–5 项，过期的删掉>

## 当前状态（YYYY-MM-DD）

- 阶段 / 版本：
- 迭代：
- 产出：
- 核对 / 验证：
- 交付物与指纹：
- 环境：
- 阻塞 / 等待：
- 精细度：full
```

> `## 当前状态` 是**容器自选**的：有它就校验新鲜度（日期 ≥ 最后一篇记录），
> **没有不算错**（状态也可以写在每篇开头的引用块里——实测 `embeding try` 四条线根本没有台账）。
> 「项目背景 / 关键事实」也建议加上：台账的职责是"这条线在做什么 + 已核实的结论"，不只是索引。

> `精细度` 是状态块的第八个字段，取值 `full` / `session` / `digest` / `milestone`（**默认 `full`**），
> 由 `journal.py mode --set …` 维护；`（原因：…）` 是可选的一行切换理由（见 `conventions.md`「记录精细度」）。

> ⚠ 索引表里那行 `[0001-示例.md]` 是**格式示例**；`check` 会把指向不存在文件的链接判成
> `ERROR 死链`（见 `conventions.md`）。初始化后**删掉该行**（或改成真实文件名），
> 此时 `journal.py check` 在 0 篇记录下才应是 0 error。

## 3. 归档索引模板（`work_log/ARCHIVE.md`）

```markdown
# 归档区

| 目录 | 篇号 | 时间 | 内容 | 归档判据 |
|---|---|---|---|---|
| `<阶段>/` | 0027–0045 | YYYY-MM-DD ~ | <一句话> | <阶段收口 / 索引停止增长> |

编号体系与容器根一致，**归档不改号、内容不删**。主索引见 [README.md](README.md)、
归档记录见 [`<阶段>/`](<阶段>/)。归档阶段目录直接建在容器下，**没有** `archive/` 一层。

## 引用换算

- `0027-x.md`（归档前，容器根）→ `<阶段>/0027-x.md`
- `lessons/` 的 `wl/0027` 是纯编号引用，不受目录变化影响。
- **日期式容器没有编号**：表里的「篇号」一列改写日期区间（`2026-08-31 ~ 2026-09-19`），
  引用换算写文件名（`2026-09-02-x.md` → `<阶段>/2026-09-02-x.md`）。
```

## 6. 经验索引模板（`work_log/lessons/README.md`）

```markdown
# 经验手册

项目里**踩过的坑、验证过的技巧、事故档案与协作纪律**都收在这里，每条标注来源篇号。

| 分册 | 内容 |
|---|---|
| [01-<topic>.md](01-<topic>.md) | <一句话> |

## 使用方式

- **动手前**：查对应分册的易错点。
- **排查时**：先查事故档案分册，症状对得上就看根因与做法。
```

## 8. 目标表模板（`work_log/目标.md`，**需要时才建**）

多个长期目标并行、各自处于不同阶段时才建这个文件；只有一个目标时台账的 `## 项目背景` 够用。
**缺它是正常的**——`check` 不报任何东西。约定见 [conventions.md](conventions.md)「目标」。

```markdown
# 目标

| 目标 | 阶段 | 状态 | 相关记录 |
|---|---|---|---|
| <长期目标 A> | <阶段一> | 已完成 | 0007, 0012 |
|  | <阶段二> | 进行中 | 0021 |
|  | <阶段三> | 未开始 | — |
| <长期目标 B> | — | 进行中 | 0009 |
| <长期目标 C> | <它唯一的阶段> | 已放弃 | — |
```

> 规则：**续行的「目标」留空**（那一行是上一行那个目标的下一阶段）；单阶段目标的「阶段」写 `—`；
> 「相关记录」写**真实存在**的篇号（`check` 会校验，写不存在的篇号会报 ERROR），没有写 `—`；
> 「状态」**人工维护**，只能写 `未开始` / `进行中` / `已完成` / `已放弃`。
