# 模板（复制即用）

> 占位符：`<项目>`、`<阶段>`、`NNN`（篇号）、`YYYY-MM-DD`、`N`（迭代号）。
> 目录一律写成默认容器名 `work_log/`（容器名可配置，见 [conventions.md](conventions.md)「目录布局」）。
> `journal.py new` 用「记录模板」自动生成文件（**编号式**；一~五节是从前的必填结构，现在是可选骨架）；
> 其余模板在初始化项目时手工落盘一次。
> `## 六、更正` 不在自动生成的正文里——它由 `append --section 更正` 在需要时追加（标题不带编号）。

## 0. 先选命名约定（一个容器只用一种）

| 约定 | 文件名 | H1 |
|---|---|---|
| **编号式** | `NNN-<slug>.md`（纯中文标题可用 `NNN.md`；也允许 4 位） | `# NNN · <一句话标题>` |
| **日期式** | `YYYY-MM-DD-<slug>.md` | `# YYYY-MM-DD <一句话标题>`（日期后可接行内实验号 `R21：`） |

- 两种都要求 **H1 与文件名一致**；**两种都不匹配的文件不是记录**，工具会忽略它。
- 编号式：编号**单调递增、永不复用、归档不改号**；回指写 `wl/NNN`。
- 日期式：不分配编号，同一天可以多篇（实测最多一天 8 篇），靠标题区分；回指写文件名。
- 一个容器内**建议只用一种**（混用会让排序与索引变乱）；混用不报错，只提示一句。

## 1. 记录模板（`work_log/NNN-slug.md` 或 `work_log/YYYY-MM-DD-slug.md`）

**下面这五节是从前的必填结构，现在是「模板之一」。** 小节结构自由：唯一的硬要求是**一个验证类小节**，
而且它必须有可核对的结果（数字 / 百分比 / 命令输出 / 表格），只写设置不算。

```markdown
# NNN · <一句话标题>                       ← 编号式；日期式写 `# YYYY-MM-DD 一句话标题`

日期：YYYY-MM-DD
迭代：N
触发：<为什么做这件事；用户请求 / 缺陷 / 计划项>
范围：<改了哪些文件或模块；明确不做什么>
结论：<一句话结果 + 关键数字>

---

## 一、背景与事实核查

<只写核实过的事实：命令、文件、输出、版本号。不确定的标「未核实」并说明怎么核。>

## 二、方案与取舍

<选项 A / B、代价对比、用户拍板的结论；没有选项时写清为什么只有这一条路。>

## 三、执行

| 对象 | 改动 |
|---|---|
| `<对象>` | <一句话> |

## 四、验证

- 方式：`<命令 / 数据 / 引用 / 样本>`
- 结果：<通过数 / 数字 / 百分比 / 关键输出——**这一行不能空**，只写"设置"不算验证>
- 未覆盖：<没验的部分与原因>

## 五、遗留与下一步

- [ ] <未完成项，交给谁 / 什么条件下做>

## 六、更正（仅在推翻旧结论时追加，平时删掉本节）

- YYYY-MM-DD：原结论「…」→ 新证据「…」→ 现结论「…」。
```

> **入口字段都可选。** `日期：` 在日期式容器里可以不写（日期已在文件名与 H1 上）；
> `迭代：` 可省；`变更集` 只是迭代字段的一个别名，写「无」或干脆不写都不算错。
> 引用块式入口（`> 状态：… ｜ 工具：… ｜ 产物：…`）同样是合法写法，见 conventions.md「记录入口」。

> **日期式的最小记录**（没有六段式、没有 `日期：` 行，照样过门禁）：

```markdown
# 2026-09-06 门控两段式

> 状态：**已完成** ｜ 工具：`mini_bert.py` ｜ 产物：`exp/gate_10k.json`

## 设置

MLM 10k → sim NCE 5k，4×256×8。

## 结果

| 项 | ρ |
|---|---|
| 门控两段式 | 0.4973 |
| 门控从头 | 0.5049 |
```

## 2. 台账模板（`work_log/README.md`）

```markdown
# <项目> 工作记录

> 可复用的坑/技巧/教训见 [`lessons/`](lessons/README.md)；本目录只放逐个可交付单元的过程记录。

## 项目背景
- 目标：
- 方案：

## 关键事实（已核实）
- <核实过的、以后会反复用到的结论>

## 文件索引

### A. <阶段名>（YYYY-MM-DD ~ ）

| 文件 | 方面 |
|---|---|
| [0001-示例.md](0001-示例.md) | <一句话> |

## 同主题簇

- **<主题>**：0001、0002 —— <一句话演进>

## 待办（滚动清单）

- [ ] <未完成项>
- [x] <最近完成的 3–5 项，过期的删掉>

## 当前状态（YYYY-MM-DD）

- 阶段 / 版本：
- 迭代：
- 产出：
- 核对 / 验证：
- 交付物与指纹：
- 环境：
- 阻塞 / 等待：
- 精细度：full
```

> `## 当前状态` 是**容器自选**的：有它就校验新鲜度（日期 ≥ 最后一篇记录），
> **没有不算错**（状态也可以写在每篇开头的引用块里——实测 `embeding try` 四条线根本没有台账）。
> 「项目背景 / 关键事实」也建议加上：台账的职责是"这条线在做什么 + 已核实的结论"，不只是索引。

> `精细度` 是状态块的第八个字段，取值 `full` / `session` / `digest` / `milestone`（**默认 `full`**），
> 由 `journal.py mode --set …` 维护；`（原因：…）` 是可选的一行切换理由（见 `conventions.md`「记录精细度」）。

> ⚠ 索引表里那行 `[0001-示例.md]` 是**格式示例**；`check` 会把指向不存在文件的链接判成
> `ERROR 死链`（见 `conventions.md`）。初始化后**删掉该行**（或改成真实文件名），
> 此时 `journal.py check` 在 0 篇记录下才应是 0 error。

## 3. 归档索引模板（`work_log/archive/README.md`；用了归档层的项目才需要）

> **人写为主、工具只补行。** 这份文件是归档目录**自己的**索引：一行一个阶段，
> 明细不往容器根台账里堆（冷数据不进热面；根 README 只留一句指针，见 `conventions.md`
> 「子目录自述」）。`check` 不管它的正文，`archive --stage archive/<…>` 只做两件事：
> 表里没有这个阶段就**追加一行**，已经有一行就**原地合并**（日期区间取并集；篇号与篇数
> 按目录里的实际记录重算，不并入旧格里的数字）。
> 文件不存在时，工具会建一份和下面骨架一样的最小版本；有人写过的自述、备注、
> 别的表格一律不动。第一次归档之后按需补自述即可。

```markdown
# `work_log/archive/` —— 已归档记录

一句话说明这里放什么（例如「只放告一段落的内容；编号体系见 [../README.md](../README.md)」）。

| 目录 | 篇号 | 时间 | 内容 | 归档判据 |
|---|---|---|---|---|
| `工作记录/01-起步/` | 0001–0005 | 2026-09-26 ~ 2026-09-28 | 5 篇 | 阶段收口 |
| `工作记录/02-调研/` | 0006–0012 | 2026-09-29 ~ 2026-10-02 | 7 篇 | 阶段收口 |
| `ops/01-安装/` | 0013–0018 | 2026-10-03 ~ 2026-10-05 | 6 篇 | 按主题线收口 |

编号体系与容器根一致，**归档不改号、内容不删**。主索引见 [../README.md](../README.md)。
```

表头**必须**是这五列（工具靠这一行认表；改了列名，写入会变成"另起一张表"）。
「目录」列写**相对 `archive/` 的路径**（`工作记录/01-起步/`）—— 与容器根台账里
那种写全路径（`archive/工作记录/01-起步/`）的行**不一样**，两者混起来会得出全错的读数，
所以这一列不要照抄台账。「归档判据」是**人写**的一列（`阶段收口` / `按插件拆主题线` /
`索引停止增长` …），**工具合并那一行时会原样保留**它，只有空着才填默认的 `阶段收口`
（2026-10-17 改：从前这里写"会被重置成默认值"，那是把当时的缺陷写成了规格）。
「篇号」与「内容」两列里的数字由工具按磁盘重算：篇号连续写区间、有断档写穷举，
篇数按**编号式**记录数（日期式记录没有篇号，不参与这两列）。

> 归档目录**直接建在容器下**的项目（短项目最省事，没有 `archive/` 这一层）不需要这份文件：
> 既然没有归档层，归档明细就在台账的文件索引里，用 `index compact --stage X` 折成一行区间。

> 容器里若还留着**旧的** `# 归档区` 表（`work_log/ARCHIVE.md` 或 `work_log/archive/ARCHIVE.md`），
> 那份已退场（2026-10-16）：`archive` 不再写它，`check` 只出一条 INFO 提示可删 ——
> 它那一列写的是相对**容器根**的路径，别和新索引的那一列混着抄。

## 引用换算

- `0027-x.md`（归档前，容器根）→ `<阶段>/0027-x.md`
- `lessons/` 的 `wl/0027` 是纯编号引用，不受目录变化影响。
- **日期式容器没有编号**：表里的「篇号」一列改写日期区间（`2026-08-31 ~ 2026-09-19`），
  引用换算写文件名（`2026-09-02-x.md` → `<阶段>/2026-09-02-x.md`）。
```

## 5. 经验分册模板（`work_log/lessons/NN-topic.md`）

```markdown
# NN · <主题>

来源：<本分册材料来自的记录范围，如 `wl/0046`–`wl/0151`，或日期式的文件名列表>。

## <子主题>

- **<症状>**：<现象>。根因：<机制>。做法：<正确做法>。（`wl/0042`）
```

条目默认一行。**复发过或代价极大**的写成卡式 —— 主行不变，后面跟**缩进 2 空格**的子条目：

```markdown
- **<症状>**：<现象>。根因：<机制>。做法：<正确做法>。（`wl/0042`）
  - 触发：<任务描述里会出现的现象词，用「/」连同义词>
  - 验证：<怎么确认这次真的成了；别拿「没报错」当成了>
  - 别再来：<不通的路 1>（<报错原文 / 机制原因>）；<不通的路 2>（<原因>）
```

触发词写**任务里会出现的词**，不写学科名：反例 `触发：客户端插件样式`，正例
`触发：改完 lib/client.js，邻居界面丢样式`。用 `journal.py lesson add --trigger … --verify … --avoid …`
生成；`check` 校验触发与验证必须成对（只出现一个报 WARN，`--strict` 升 ERROR）。

## 8. 目标表模板（`work_log/目标.md`，**需要时才建**）

多个长期目标并行、各自处于不同阶段时才建这个文件；只有一个目标时台账的 `## 项目背景` 够用。
**缺它是正常的**——`check` 不报任何东西。约定见 [conventions.md](conventions.md)「目标」。

```markdown
# 目标

| 目标 | 阶段 | 状态 | 相关记录 |
|---|---|---|---|
| <长期目标 A> | <阶段一> | 已完成 | 0007, 0012 |
|  | <阶段二> | 进行中 | 0021 |
|  | <阶段三> | 未开始 | — |
| <长期目标 B> | — | 进行中 | 0009 |
| <长期目标 C> | <它唯一的阶段> | 已放弃 | — |
```

> 规则：**续行的「目标」留空**（那一行是上一行那个目标的下一阶段）；单阶段目标的「阶段」写 `—`；
> 「相关记录」写**真实存在**的篇号（`check` 会校验，写不存在的篇号会报 ERROR），没有写 `—`；
> 「状态」**人工维护**，只能写 `未开始` / `进行中` / `已完成` / `已放弃`。

## 9. 踩坑收件箱模板（`work_log/_inbox.md`）

踩到坑的**当时**记一行，别等收尾 —— 收尾靠回忆，回忆不可靠。它不是记录、也不是经验分册
（与 `.lore-inbox/` 那个跨工作区消息目录无关）；收尾时把够格的整理进 `lessons/` 并删掉那一行。

```markdown
# 待整理（踩坑当场记一行）

> 不是记录，也不是经验分册；与 `.lore-inbox/`（跨工作区消息）无关。
> 收尾时把够格的（复发过的 / 代价大的）整理进 `lessons/`，删掉那一行；小意外留着下次。

- YYYY-MM-DD ｜ <现象> ｜ <一句话解法 / 线索> ｜ 证据：<命令 / 路径 / 会话>
```

## 10. AGENTS.md 钩子（可选）

**不要自动写**：不同宿主认的指令文件不同，初始化时**问一次**要不要写进本项目的
`AGENTS.md` / `CLAUDE.md`，得到答复再落盘。约 0.5 KB，只在有这个文件的项目里付常驻成本。

```markdown
## 经验层（work_log/lessons）

- **动手前**：任务里出现「<现象词 1> / <现象词 2>」这类现象，先搜经验再答：
  `grep -rn "<现象词>" work_log/lessons`（PowerShell：`Select-String -Path work_log\lessons\*.md -Pattern "<现象词>"`）。
  命中哪条读哪条；卡少时列目录挑，一样算数。
- **踩到坑的当时**：只要这次是又试错了几轮、而不是照着经验做顺的，立刻往 `work_log/_inbox.md`
  记一行（现象 + 一句话解法）。别等收尾 —— 收尾靠回忆，回忆不可靠。
- **收尾时**：在说出「完成 / 搞定了 / 修好了」之前，看一眼 `_inbox.md`；够格的整理进 `lessons/` 并删那行。
```

> 现象词抄本项目的真实症状（说人话、能被任务描述命中），不要抄模板里的占位词。
